# Task6 ユーザテスト結果に基づく修正 - 実装ガイド

## 📋 修正の全体像

ユーザテストで発見された問題を4つの独立した修正に分けて、段階的に実装します。各修正は独立しているため、1つずつ実装・テストを進めることで、問題が発生した場合も特定しやすくなります。

---

## 🎯 修正一覧

| 修正 | 内容 | 優先度 | 難易度 | 所要時間 |
|------|------|--------|--------|----------|
| **Fix1** | サイドメニューのスワイプ感度改善 | 高 | 低 | 10分 |
| **Fix2** | 記事詳細画面のブックマークボタン削除 | 中 | 低 | 15分 |
| **Fix3** | 引用メモの文字数制限を300文字に緩和 | 中 | 中 | 20分 |
| **Fix4** | URL安全性の基本バリデーション追加 | 高 | 中 | 30分 |

**合計所要時間**: 約75分（テスト時間含む）

## 🚀 推奨実装順序

### ステップ1: Fix1（スワイプ感度改善）
- **理由**: 最も簡単で影響範囲が小さい
- **ファイル**: `HomeView.swift` のみ
- **変更**: 3つの数値を変更するだけ

### ステップ2: Fix2（ブックマークボタン削除）
- **理由**: UI要素の削除のみで、ロジック変更なし
- **ファイル**: `ArticleDetailView.swift` のみ
- **変更**: ボタン要素の削除

### ステップ3: Fix3（文字数制限緩和）
- **理由**: 複数ファイルの変更が必要だが、パターンは単純
- **ファイル**: 複数（バリデーション、エラーメッセージ、テスト）
- **変更**: 140を300に変更

### ステップ4: Fix4（URLバリデーション）
- **理由**: 最も複雑で、新規メソッド追加とエラーハンドリングが必要
- **ファイル**: Repository、ViewModel、View
- **変更**: 新規メソッド追加、エラー型定義、UI更新

## 📝 実装時の共通ルール

### 1. コメント規約
各変更箇所に以下のコメントを追加：
```swift
// Task6 User Test Fix: [修正内容の簡潔な説明]
```

### 2. クリーンビルド
各修正後は必ずクリーンビルドを実行：
```bash
Cmd+Shift+K  # クリーン
Cmd+B        # ビルド
```

### 3. テスト実行
各修正後は全テストを実行：
```bash
Cmd+U  # 全テスト実行
```

### 4. Git コミット（推奨）
各修正完了後にコミット：
```bash
git add .
git commit -m "[Task6 Fix1] サイドメニューのスワイプ感度改善"
```

## 🐛 トラブルシューティング

### 問題: ビルドエラーが発生
1. エラーメッセージを確認
2. 変更箇所を再確認
3. 必要に応じて前の修正に戻す（Gitを使用している場合）

### 問題: テストが失敗
1. 失敗したテストを特定
2. テストコードも更新が必要か確認
3. 修正指示書のテスト手順を再確認

### 問題: 既存機能が動作しない
1. 変更範囲を最小限に抑えているか確認
2. 削除しすぎていないか確認
3. 必要に応じて修正を一時的に元に戻す
